# ADR 0009 · 首个管理员首次登录必须改密

- **状态**：Accepted
- **日期**：2026-11-05
- **机制**：见 F1 §1.4 / §1.7 / §1.9；验证台账 `I-V19`

## 背景

首个管理员由部署命令一次性建出，初始口令必须经过运维的手。它可能被写进
部署记录、贴进聊天、或临时交给另一个人；如果它就是长期口令，这次引导
等于制造了一个永久有效的共享凭据。

当前系统没有任何地方记录“这个账号还没改初始口令”。只靠文档要求“登录后
请改密”，既不可验证，也不会在有人忘记时提醒任何人。

## 决定

给 `users` 增加 `must_change_password`，只在引导与管理员重置时置 1，
本人改密时清 0。请求侧在票据/账户判定之后、业务路由之前检查它：改密前，
除 `/api/auth/me`、`/api/auth/logout`、`/api/auth/password` 外一律 403
`password_change_required`。

存量账号迁移默认 0，不强制改密；只有新引导的管理员是 1。

## 后果

好处：

- 引导口令不再能长期使用；用户第一次进业务面之前必须先轮换。
- 管理员重置后的临时口令也走同一条路，不会成为另一个长期口令。
- 状态在库里，服务端可强制、可查询、可测试；前端只负责把人送到改密页。

代价：

- 多一列、一次加列迁移，以及一个 403 错误码。
- 当前有部署库没有 `alembic_version`，所以启动期要能做一次向后兼容的加列；
  这是刻意例外，只允许加列，不允许删列/改类型/数据重写。
- 首次登录多一步操作；这是安全与体验的明确取舍。

## 什么情况下该重开

- 客户要求全部存量账号也强制轮换：需要一条显式的运维/迁移命令，不能改默认值。
- 引入 SSO/LDAP：首个管理员可能由 IdP 组映射产生，这条本地引导路径要重新定位。
- 要做定期强制换密/密码历史：`must_change_password` 只解决首登，不承担策略引擎。
