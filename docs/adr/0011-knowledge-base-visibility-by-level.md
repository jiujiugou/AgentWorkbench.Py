# ADR 0011 · 知识库按账号等级可见，管理权限与内容权限分离

- **状态**：Accepted
- **日期**：2026-11-06
- **机制**：见 F1 §1.10、F2 §1.6、F3 §1.8、F5 §1.11；接口契约另定

## 背景

当前系统的权限边界只有团队：`documents` 带 `tenant_id`，检索只按团队过滤，团队成员能看到本团队的全部知识。这个模型能证明“跨团队不串”，但不能回答“同一团队里，哪些资料只给某个等级的人看”。

实际需求已经收敛为：

- 管理员可以增删改查账号（删除 = 停用），并设置账号等级；
- 存在公共知识库与私人知识库；
- 私人知识库按账号等级授权；
- 管理员不能因为“是管理员”就自动看到私人知识库内容；
- 账号不硬删除，避免会话、轨迹和文档归属断链；
- 账号等级降低后，历史引用与轨迹证据按当前等级过滤，答案正文保留。

这不是多部门需求，不需要“公司—部门—小组”组织树，也不需要一人多部门。它只是新增一个“知识库可见性”的权限维度。继续把权限只锁在团队边界，会让公共/私人知识库退化成命名约定，管理员也无法在“能管账号”和“能看内容”之间被区分开。

## 决定

1. **知识库是授权单位，文档继承知识库可见性。**
   - `public`：本团队所有有效账号可读。
   - `private`：只有账号等级达到 `min_level_rank` 的账号可读。
   - 不做逐文档 ACL，也不做部门级/岗位级授权树。
   - 同一份文件可以分别存在于不同知识库；去重与文件归属按知识库，不跨库共享行或文件。否则把文件从私人库挪到公共库会等于一次隐式发布。

2. **账号等级与团队角色是两根轴。**
   - `role` 继续回答“能不能管账号”。
   - `level` 回答“能看哪些知识库”；等级有序，第一版固定为 L1~L5（名称可配置）。
   - 不把等级塞进 `ROLE_RANK`，也不把管理员角色当成内容通行证。

3. **管理员没有内容后门。**
   - 管理员等级不够时，只能看知识库元数据，不能看文档列表、正文、引用和轨迹证据。
   - 管理员不能修改自己的等级。
   - 管理员不能给账号设置高于自己的等级。
   - 管理员不能重置高于自己等级账号的密码。
   - 更高等级由更高等级管理员或部署 CLI 设置；平台管理员同样不默认绕过内容权限，也不能靠平台标志重置高等级账号的密码。

4. **账号只停用，不硬删除。**
   - 停用后不能登录，历史会话、轨迹和文档归属保留。
   - 不提供 hard delete，除非未来另有资产转移与留存策略。
   - ADR 0008 的“删除文档仅团队管理员”仍成立；本 ADR 只增加一道知识库可见性门槛，不把删除权下放给成员。

5. **历史按“引用/证据过滤、正文保留”处理。**
   - 读取历史引用与轨迹证据时，按用户**当前**等级重新判断来源知识库。
   - 不可访问的来源只显示“来源已不可访问”，不显示文件名与原文片段。
   - 答案正文不追溯删除；正文里已经出现的高等级内容仍可能可见。这是本决定明确接受的残余风险，不假装实现了完整的追溯撤销。

6. **存量数据不改变现有行为。**
   - 每个团队创建默认公共知识库。
   - 现有文档全部归入默认公共库；原团队内去重规则改为按知识库去重。
   - 团队边界（`tenant_id`）继续是最高层隔离，不因知识库等级而放宽。

## 后果

**好处**

- 公共/私人知识库有真实的权限落点，不再是命名约定。
- 不需要引入部门树或一人多部门，权限模型仍是二维：账号等级 × 知识库可见性。
- 管理员可以管账号，但不能靠角色直接读私人内容；内容权限与管理权限可以分别审计。
- 现有执行轨迹、拒绝记录、引用和评测体系可以保留。

**代价**

- 新增账号等级、知识库归属与管理员操作审计的迁移。
- 文档列表、详情、页、chunk、上传、删除、重解析，以及检索的词面路和向量路，都必须按知识库过滤；漏一条就是越权。
- 管理员不能再管理高于自己等级的账号；高等级账号的创建、停用与密码重置需要更高等级管理员或部署 CLI。这是为了让“管理员不能看私人库”成为真实边界，而不是界面隐藏。
- 历史引用与轨迹证据需要新的读侧过滤；答案正文保留会留下残余内容，不能对外承诺“降级后完全看不到旧内容”。
- 现有验收中“同团队所有人可见全部文档”的断言需要改写，并新增等级矩阵测试。

## 什么情况下该重开

- 需要“私人知识库只属于某个创建者”，而不是按等级开放：新增 owner 维度，重写可见性规则。
- 需要“管理员能管理所有账号，但仍不能看私人内容”：必须引入独立的安全管理员/双人授权，或接受管理员可重置高等级密码带来的冒充风险；不能只删掉现有约束。
- 需要“降级后连历史答案正文也不可见”：新增正文脱敏/冻结策略与审计留存规则，不能沿用本决定。
- 需要部门树、一人多部门或跨部门授权：这是另一个权限模型，应另写 ADR，并重新评估 Yuxi/商业平台，而不是在知识库可见性上继续叠。
- 需要任意层级的等级树或等级可自由新增：先定义等级排序与授权上限，再改等级模型。
