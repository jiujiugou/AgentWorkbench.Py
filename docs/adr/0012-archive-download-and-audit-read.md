# ADR 0012 · 归档、原件下载与管理员审计读取

- **状态**：Accepted
- **日期**：2026-11-06
- **机制**：见 F1 §1.10、F2 §1.5/§1.6；接口契约另见 API 声明表

## 背景

知识库已经有可见性和等级授权，但还有三个出口没有收口：

- 前端有「原件」入口，后端却没有下载路由；如果直接挂静态目录，会绕过团队与知识库可见性。
- `knowledge_bases.archived_at` 已存在，但没有归档/取消归档接口；如果拿删除代替归档，会话、引用和文档归属会断链。
- `admin_events` 只写不读。管理员看不到「谁改了账号/等级/知识库」，事故后只能查库。
- 停用/恢复、发邀请还没有写审计，账号变更链不完整。

这三件事共同的风险不是「少一个按钮」，而是**同一个可见性判断只在一个出口上生效**：列表挡住了，下载/归档/审计的另一个出口没有挡。

## 决定

1. **原件下载是内容读取，不是静态文件访问。**
   - 与文档列表、正文、页、chunk 使用同一组团队 + 可访问知识库条件。
   - 磁盘路径必须解析到存储根之内；下载文件名取数据库里的 `file_name`，不从路径反推。
   - 不可见、已归档、文件缺失一律 404，不返回路径或磁盘错误。
   - 不新增静态目录挂载，也不允许绕过 `documents.kb_id` 的可见性判断。

2. **归档是可逆的软状态，不是删除。**
   - 默认公共知识库禁止归档；归档后不能再上传、重解析或读取内容。
   - 归档只改变「是否参与列表/检索/下载」，不删除文档、块、引用快照和磁盘文件。
   - 管理员仍能看到归档知识库的元数据，并可取消归档；成员看不到归档库。
   - 归档/取消归档写 `admin_events`，动作分别为 `kb.archive` / `kb.unarchive`。

3. **`admin_events` 的读侧只对管理员开放，且按团队隔离。**
   - 追加写、不可改；读接口只读，不提供编辑/删除。
   - 只返回审计字段，不回显请求体、口令、token 或文件内容。
   - 默认按时间倒序，带 limit 与 before 游标；过滤条件至少支持 action、resourceKind、resourceId、actorUserId。

4. **默认库和重名是数据完整性约束，不交给界面。**
   - 默认公共库不能改可见性、不能归档。
   - 同一团队内知识库重名返回明确的 4xx，不把 SQLite 唯一约束冒成 500。

5. **账号生命周期审计补齐。**
   - 停用/恢复写 `user.disable` / `user.enable`。
   - 邀请创建写 `invite.create`；不记录明文 token，只记录邀请 id 与角色。
   - 接受邀请的账号创建由现有账号创建路径记录，不把一次自建号伪装成管理员操作。

## 后果

**好处**

- 原件下载与正文读取共用一套权限，不会再出现「列表看不到但直链能下」。
- 归档可撤销，不需要用「删除文档」承担知识库下线的职责。
- 审计从只写变成可查，事故后能回答谁在什么时候改了哪个账号或知识库。
- 默认库不会因一次改名/改可见性把存量资料变成不可见。

**代价**

- 归档库的文档仍然占磁盘和索引空间；清理是运维策略，不在归档动作里做。
- 审计查询需要新的分页与过滤契约；数据量上来后要关注索引与保留策略。
- 下载必须经过应用层，不能依赖反向代理直接读文件目录；大文件会占用服务端连接。
- 管理员仍可能看到归档库的元数据；这是为了可恢复，不是内容读取。

## 什么情况下该重开

- 需要「归档后自动删除文件与索引」：先定义留存、引用快照和恢复策略，不能把它塞进归档按钮。
- 需要「成员也能看归档库」：这是可见性规则变更，必须另写 ADR 并重跑 M11–M14。
- 需要「审计记录可编辑/可删除」：破坏追加写，必须先定义合规留存与双人授权。
- 需要把原件下载改成签名 URL 或对象存储直链：必须证明 URL 本身不会绕过知识库可见性。
