> **口径（2026-11-06，已冻结）**：本文描述**单进程 Python 版（v1.x）**的功能口径，不再修订。

> 这一节不得当作新产品的设计约束引用。
> **现行归属正本**：`docs/架构/能力矩阵-七层填空.md` 附录 C；运行时边界见 ADR 0016。

一句话：**用户问一个问题，系统在本地资料里找到原文，给出带出处的答案；找不到就说找不到。**

本文写"应该是什么"和判据。**现状与数字只在第四节**，21 项明细在《F3-功能验证》，理由与赌注在《F3-决策记录》。三份不互相复制。

### 一、这个域要实现什么

#### 1.1 三条需求，就是三条不变量

| REQ | 不变量 | 给谁用 | 解决什么 | 不满足会怎样 |
|---|---|---|---|---|
| **REQ-07** 知识检索 | **可用** | 一线工程师、售后、新员工 | 不用翻几十本 PDF，问一句就落到原文那几块 | 产品没有入口，其余两条无从谈起 |
| **REQ-08** 引用展示 | **可核** | 要签字、要担责、要拿答案去现场的人 | 文档名 + 位置 + 原文片段，三者缺一不可 | 用户只能选择信或不信；"有出处"本身是一种担保，指向错块比没有出处更危险 |
| **REQ-09** 无证据时说明 | **不编** | 所有人，尤其是"信了就出事"的场景 | 检索不到足够证据时明确说资料不足，不把常识伪装成企业文档 | 编造被包装成专业建议——**比不答更危险**，因为它会被信任 |

三条不是三个功能，是一个功能的三条不变量：去掉可核，可用的后半段（"模型真用了资料"）没有任何观测点；去掉不编，前两条不算完成；去掉前两条，不编的阈值定不出来。**没有"完成三分之二"这种算法。**

**验收顺序只能按证据依赖排：先用、再可核、最后不编。** 这不是排期：找不到材料，后两条无从谈起；可核提供不编的证据（无出处句比例）；不编的两个阈值，一个要可用的距离分布，一个要可核的引用台账。按危害排恰好相反，但顺序只看证据，不看危害。

REQ-07 有一条硬条件：**只查当前团队且当前账号可访问知识库里的资料**。团队边界与知识库可见性都是查询条件，不是提示词；Python 版把这两层都当第一条不变量的组成部分，不当后续优化。

#### 1.2 形态是四段流水线，不是 agent 循环

```
用户提问（原话，不改写）
 │
 ├─① 检索：一次，前五块 ──────────────┐
 │                                    │ 证据只此一份
 ├─② 判定：四值 + 原因 ◄──────────────┘
 │      └─「资料不足」→ 终止 + 固定文案（③④ 不执行）
 ├─③ 生成：只能引用本次编号 [1..n]
 └─④ 引用校验：一级范围 → 二级支持 → 报告给界面
```

图只画顺序与失败落点，不画参数。每一段的输入→输出、失败时用户看到什么、被哪些子问题覆盖，**只在一处写**：§1.7 的功能流程总表。那张表是本域功能流程的权威，这里不重复。

**为什么不是循环：系统预检索。** 用户一提问就先检索一次，不等模型决定查不查。

这条不是偏好，是实测推翻后的结论。A-02 那条假设——"模型会遵守六条指令，先检索再答"——现在有反证：

| 依据 | 事实 |
|---|---|
| A-02 已被推翻 | 同一后端同一模型四次问答，**一次 `iterations=1, tools=0`、10 句零出处**（q03，run 18），模型直接凭常识列了六条排查建议 |
| 判定要挡在生成前 | 循环里判定只能发生在"模型决定查了之后"，位置天然在生成之后或之中 |
| 没有可选的路由 | 只有一个检索工具、一次调用；没有分支可走，写成图只多一层间接 |
| 记录权 | 循环每一步由框架调度，本域要把"查到什么、判成什么"写进 run 记录，调度权必须在自己手里 |

预检索把两件事一起解决了：证据一定在手；`[n]` 不再依赖模型主动。它**不**解决"模型用了证据"——那要靠 ② 和 ④，仍然在代码里。

预检索让三处变薄，这是要写进设计的连带后果：

| C# 版的位置 | 现在 | 为什么 |
|---|---|---|
| `SearchKnowledgeTool` 由模型调 | 前置检索，必调一次 | 调不调不由模型决定 |
| `IToolResultVeto` 挂在工具执行管道 | 生成前的门（`guard/veto.py`） | 判据不变，位置前移；执行管道不认识知识库这条仍然成立 |
| `AgentLoop` 多轮迭代 | 通常 1 次模型调用 | `agent/loop.py` 只留迭代预算、墙钟超时、重复调用三个守卫 |

#### 1.3 判定必须在生成之前，且必须写在代码里

**prompt 里的约束只是请求，不是保证。** 同一份指令，四次真跑里一次完全失效。

| 手段 | 性质 | 证据 |
|---|---|---|
| 六条模型指令（先检索、写 `[n]`、只依据资料…） | **请求** | 真跑里抓到一次不检索（run 18）；也抓到一次整段零角标（q03） |
| 否决层（生成前门） | **保证** | 判不足 → 终止，模型只被请求 1 次（3 条成对断言） |
| 引用校验两级 | **保证，但二级判别力待修** | 覆盖率在 3 组同主题邻块上只有 0.091 / 0.125 / 0.000 |

判定输出四个取值，加一个原因。系统失败不在其中——那是运行状态，不是判定结论。

| 取值 | 含义 | 之后发生什么 | 界面上 |
|---|---|---|---|
| 已回答 | 有明确赢家，且足够近 | 放行，答案必须挂出处 | 正常 + 角标 |
| 依据较弱 | 够近但没有赢家，或只有一条参照 | 放行，加"建议核对原文" | 正常 + 提示 |
| 资料不足 | 判不足 | 终止生成 | 固定文案，**不显示**句级摘要与来源列表 |
| 未判定 | 系统没有能力判断（缺向量，或阈值缺失） | 放行，但必须说出来 | 独立提示，长得和已回答不一样 |
| 失败 | 不是判定结论 | run 失败码 | 错误态 |

阈值可空（D-12）是**函数层**语义；**部署层不允许带着空阈值上线**，机制见 §4.5。

#### 1.4 引用两级校验，第二级才是难点

| 级 | 判什么 | 抓得住 | 抓不住 | 现在 |
|---|---|---|---|---|
| 一级 | 角标 `[n]` 指向的块确实存在，且属于**本次**检索结果 | "引用了不存在的块""引用了上一轮的证据" | "块存在，但与这句话无关" | 15 条测试通过 |
| 二级 | **块内容真的支持这句话** | 同主题误挂（号码对、内容不对） | — | **不通过**：5 组同主题邻块里 3 组分不开 |

一级便宜、能全自动、错误可剥离（越界标记直接摘掉）。但它只证明"编号在范围内"，不证明"这句话来自这块"。

二级的现有实现是两字组合覆盖率，可复算、不看模型脸色（D-04），代价已经出现：句子短、关键词与邻块高度重合时判别力接近零（0.091 / 0.125 / 0.000，三组的差值转记在《F3-功能验证》§4.1）。修法是 IDF 加权或关键值命中，两条都还没做。**在这一级修好之前，REQ-08 只做到"有出处"，没做到"出处对"。**

**边界要写死，否则是假承诺**：引用核实率只证明"每一句都有可核对的出处"，不证明"整段结论是从这些出处推出来的"。模型可以抄两句原文、第三句凭常识补，而那句角标恰好也能对上。文档里不许把引用写成"证明答案来自资料"。

#### 1.5 不编要覆盖三种问题，混成一档就全假了

| 档 | 题库里的题 | 条数 | 正确行为 | 靠谁兜 | 距离判得出 | 计进哪个数 |
|---|---|---|---|---|---|---|
| 完全库外 | q33 液压压力、q34 辞职信、q37 三菱 FX5U | 3 | 拒答，来源为空 | 判定 + 否决（第一层） | 能 | 拒答准确率，分子分母都是它 |
| 同主题缺答案 | q35 S7 组态、q36 H5U 保修期、q38 RTU 帧长 | 3 | **不拒**；承认"资料里没有" | 二级：让没出处的句子露出来 | **不能** | 单列"承认率"，**不进误拒率** |
| 超出检索能力 | q39 完整排查顺序、q40 critical 计数 | 2 | 拒答是假通过——资料其实在库里 | 题库标签 + 统计脚本（D-11），不进生产路径 | 不能 | 不进任何比率 |

**必须分列的数据依据**：8 条负控里 **7 条召回了 5 个块**（只有 q34"辞职信"召回为空）。这说明**检索层根本没有拒答能力**——它永远能凑出五块。所以 REQ-09 只能靠判定层，"检索为空"不能当拒答信号。这也是本域最重要的一张实测表。

**为什么不能混成一个"负例"标签**：误拒率的分母是"库内有答案的题"（32 条正例）。同主题缺答案这一档库里本来就没有那句话，正确行为也不是拒——把它塞进分母，等于把"该承认"算成"该答对"；把第三档塞进去，等于把检索的结构上限算成拒答能力。分母一错，误拒率和拒答准确率两个数同时变成假的，而且没人看得出来。

同主题缺答案这一档，现在只能靠"距离判不出"来解释（A-01，仍是假设不是结论）：问"H5U 保修期"和问"H5U 的 E2 报什么警"指向同一本手册，向量空间里几乎重叠，区别只在那一块里有没有那句话。**证伪方式**：40 题按档看第一名距离与间隔的分布，若这一档与正例明显分开，A-01 作废、第二层取消。所以本文只写"现在的量表达不了"，不写"永远不可能"。

#### 1.6 三条结构约束

这三条不是某一段的做法，是整条链路的性质。破一条，前面每段都做对了，结果仍然是坏的。

| 约束 | 破了会怎样 |
|---|---|
| **证据只取一次**，同一份结果分发给模型、来源面板、引用校验 | 检索两次排序可能不同，出现"面板显示这批、答案引那批"，**而且不报错** |
| **引用编号空间封闭**，候选取自本次证据，每次从 1 起算 | 编号能指向本次之外的东西，等于给出一句无担保的担保 |
| **判定必须可见**：已回答 / 依据较弱 / 资料不足 / 未判定 / 失败，五种在界面上长得不一样 | 判了但用户看不出，判定等于没做；最危险的"有答案、有引用、但引用全对不上"会混进正常答案 |

#### 功能流程总表（本域流程的权威，1.2 的图只画顺序，细节全在这）

每个位置是一个开发单元，**完成的定义 = 挂在上面的子问题验证通过**——"装填做完"不是"代码写了"，是"可用五升 pass"。每一格都有人：这是"没有空段"的证据。

| 位置 | 落在哪段 | 输入 → 输出 | 失败时用户看到什么 | 被哪几条覆盖 |
|---|---|---|---|---|
| 入库与切块 | 前置（F2） | PDF → 页文本 → 块 | 上传/解析失败码，不进问答 | 可用一、可用二 |
| 分词 | ① | 块文本与查询 → 索引项（索引与查询同一函数） | 查不到——单字/短型号由 LIKE 兜底 | 可用二 |
| 召回 | ① | 用户原话 + 团队范围 → 前五块（含距离、文件名、片段序号） | 检索为空**不是**"没找到"，是"资料不足"——由判定段说，不由召回说 | 可用三 |
| 精排 | ①（暂缓） | 候选块 → 重排序列 | —（未接，等混合检索基线 + 消融） | 可用四 |
| 装填 | ①→③ | 五块 → 模型窗口内的证据 | 超预算必须告警，不静默截断 | 可用五 |
| 判定 | ② | 五块的距离 → 四值之一 + 原因 | 「未判定」必须在界面上说出来，不能显示成「已回答」 | 不编一（配套二至七） |
| 引用生成 | ③ | 证据 + 编号表 → 带 `[n]` 的正文 | 生成失败是 run 失败码，不是拒答 | 可用六、可用七、可核一 |
| 引用校验 | ④ | 正文 + 本次证据 → 越界标记、无出处句、支持结论 | 二级判不了时只能标"未核实"，不许标"已核实"；报告只给界面，**不喂下一步** | 可核二、可核三 |
| 回原文 | 界面 | 片段卡片 → 原文定位 | —（退到卡片，不做页面跳转，D-06） | 可核五 |
| 入口 | 全局 | —（接口只剩检索与索引四方法） | — | 可用八 |

装填当年就是这么漏掉的：它在链路里，却没有任何一条问过它。

#### 1.8 检索范围：团队边界 × 可访问知识库（REQ-24）

**检索的候选集不是"本团队全部块"，而是"本团队且当前账号可访问的知识库里的块"。** 这是一个查询条件，不是提示词，也不是融合后的 Python 过滤。

| 路径 | 必须带的条件 | 不允许的做法 |
|---|---|---|
| FTS 词面路 | `tenant_id = ?` 且 `kb_id IN (可访问知识库)` | 先查全团队再在应用层删结果；删漏一条就是越权 |
| 向量路 | 同样的租户与知识库条件进入 `_meta_of` 的过滤 | 只过滤最终 top-k；被过滤掉的块仍可能影响排序或出现在证据里 |
| 融合 / 重排 | 输入已经是可访问集合 | 两路各自过滤后又在融合层丢掉条件 |

**可访问集合由 F1 §1.10 与 F2 §1.6 决定**：公共库全团队可读；私人库要求 `rank >= min_level_rank`；管理员没有内容后门。检索侧不重新定义规则，只消费同一个 `accessible_kb_ids`。

**检索侧不能以任何形式留下不可访问知识库的痕迹**：

- 命中数为 0 时按"资料不足"处理，不提示"有私人资料但你没权限"，也不推荐申请权限。
- 不允许在无命中时回退到"不过滤再查一次"；那会把私人库内容带进答案。
- 引用快照必须带 `kb_id`；否则历史读取无法判断来源是否仍可见（F5 §1.11）。
- 轨迹里的检索证据同样按当前可访问集合过滤；管理员低等级时也看不到高等级私人库的证据。

**验收至少覆盖**：同一问题在公共库与私人库各有一份相似资料时，低等级账号只命中公共库；私人库低于门槛时列表、详情、检索、引用、证据全不可见；低等级管理员不因 `admin` 角色获得额外命中；跨团队仍 0 命中；等级变更后下一次检索立即使用新集合。

### 二、选用什么成熟组件

| 组件 | 解决哪条边界 | 调用点 | 换掉它的成本 | 许可 |
|---|---|---|---|---|
| **SQLite + FTS5**（unicode61） | 词面路：型号、错误码、专有名词必须精确命中；私有化单机部署不引服务 | `rag/indexer.py` 建 `chunks_fts`；`rag/retriever.py` 发 `MATCH` | 换 Postgres = 换中文分词方案 + 重建索引（见 2.1），不是换连接串 | Public Domain |
| **两字切分**（自写） | 中文没有空格；`H5U` / `E2` / `Modbus` 不被切开 | `rag/tokenizer.py`，索引与查询**必须调同一函数** | 换 jieba：多一份词典版本，换版数字就漂，且要重建索引 | 本项目代码，无第三方 |
| **LIKE 兜底** | 单字查询（"泵"）、短型号 | `rag/retriever.py` 第二路 | 极小，但要注意别把兜底当主路 | 不需 |
| **bge-m3**（embedding） | 语义路：改写题（23 条 paraphrase）唯一能救的一路 | `llm/embeddings.py` → 入库与检索 | 换模型 = 全库重算 + 分数分布变 + 两个阈值作废 | MIT |
| **bge-large-zh-v1.5** | 显存/延迟更紧时的备选。中文检索约 71.2，对 bge-m3 的约 73.5（C-MTEB 口径，**第三方汇总，用前回源模型卡核对**） | 同上 | 同上 | MIT |
| **RRF 倒数排名融合**（自写约 20 行） | 双路合并；没有权重，就没有可调的隐藏参数 | `rag/retriever.py` | 换加权求和 = 引入两个待调参数 + 需要新基线 | 算法，无许可 |
| **交叉编码器重排**（FlagEmbedding / rerankers） | 精排：正确块排第二时把它提上来 | 暂缓，未接；将来接在融合之后 | 接入后排序与分数分布同时变，旧基线不可比 | MIT / rerankers 待核实 |
| **自制评测脚本**（`evals/self/`） | 命中率、MRR、接缝率、索引一致性 | `python -m evals run` | 换框架 = 口径变，历史数字不可比 | 本项目 |
| **ranx / RAGAS** | 外部口径（nDCG、faithfulness），用来检查自建指标是否系统性偏乐观 | 未接入 | 中：双跑成本 + 口径解释成本 | MIT / Apache-2.0（待回源） |
| **RGB 负拒绝子集** | 拒答的外部校准（自建只有 3 条 off_topic） | `evals/public/rgb` | 数据许可限制：**不能进交付物** | **CC BY-NC-SA 4.0** |

#### 2.1 中文分词

FTS5 与向量扩展都不处理中文，词面路由 `rag/tokenizer.py` 的两字切分负责（索引与查询**必须调同一函数**）。不用 jieba 的理由只有一条：词典是第二份带版本的隐藏状态，换一版检索数字就漂，而且不报错。

型号与错误码原样保留（`H5U` / `Modbus` / `E2`），单字不成两字，交 LIKE 兜底。

#### 2.2 边界：块边界不交给框架

判据一句：任何让"块边界 / 块编号"脱离 `ingest` 与 `db` 的引入都不接。40 题 gold 挂在 `(file, seq)` 上，而这件事**不报错，只会让命中率悄悄归零**。表与检索 SQL 自己写。

LlamaIndex 只用两样：切块器、embedding 客户端。

#### 2.3 不选 LangGraph 当骨架

它接管调度、不接管执行，而本域要的是记录权：查到哪五块、判成什么、为什么拒，必须能回放到某一次 run。没有图可画的时候画图，只是把一条直线折成三层间接。

#### 2.4 组件选择的共同判据

| 判据 | 含义 | 反例 |
|---|---|---|
| 可复算 | 同样输入必得同样输出/分数 | 用模型判"够不够""忠不忠" |
| 可替换 | 换掉它只动一个文件 + 一次重建 | 让框架接管表结构 |
| 许可清楚 | 交付物里能出现的许可 | RGB 是 CC BY-NC-SA，只能做评测 |
| 有消费者 | 引入的每个配置项都有人读 | 一个没人读的阈值 = 一个假的机制 |

### 三、做什么是加分项

**前置一步（不算加分，是加分的前提）**：完全库外这一档现在只有 3 条（q33 / q34 / q37）。任何阈值在 3 个点上扫出来都是过拟合。先补到 15 条以上，下面第 1 项的产物才不是假的。

按 加分 ÷ 成本 排序：

| # | 动作 | 为什么加分 | 成本 | 风险 |
|---|---|---|---|---|
| 1 | **阈值网格扫描**：`run_refusal_eval.py --scan`，margin × distance 两维，候选过滤先放宽到 1.0 | 直接回答"闸开不开"；能看到每一档被判成什么，而不是只看到一个结论。这是 REQ-09 唯一的开关 | 脚本已在，成本是扩题 + 一次运行，约 1 天 | 两个数（误拒率、自信答错率）同时变坏的格子必须直接排除；3 条 off_topic 时扫出来的数不可用 |
| 2 | **消融实验**：同一套 32 正例 + 8 负控跑四组——只 FTS / 只向量 / 双路 RRF / 双路 + rerank，各报 HitRate、MRR、负控非空数、平均第一名距离 | 唯一能回答"哪一路在出力"的方法，也是 rerank 该不该上的唯一依据。**能报出"关掉某一路掉多少分"，就是判断力本身**；现在只有 `--mode fts` 一个数，向量路的贡献是零证据 | 脚本加 `--ablate` + 4 次跑，约 2 天（向量路要 embedding 服务） | 关掉 FTS 后型号/单字查询会掉，别外推成"全文路不重要"——它只在这 32 题上不重要 |
| 3 | **二级校验换判别方式**：覆盖率按 IDF 加权，或数字/型号/单位改逐条比对（`check_values.py` 的归一化函数可复用） | 误挂只发生在同主题邻块，那里现在判别力为 0（0.091 / 0.125 / 0.000）。修好它，REQ-08 才从"有出处"变成"出处对" | 1~2 天 + 5 组对照重跑 | IDF 要建词频表 = 又一份带版本的状态；关键值命中只覆盖含数字/型号的句子，纯文字结论仍靠覆盖率 |
| 4 | **RGB 负拒绝子集做外部校准**：转成 (question, 应拒) 格式，只跑判定层不跑生成 | 自建集只有 3 条库外题，外部集是唯一能说"不是我一个人觉得好"的证据 | 约 2 天（格式转换 + 跑 + 抽检） | **CC BY-NC-SA 4.0**：不能打包进交付物；英文为主，中文迁移要人工抽检 20 条 |
| 5 | **claim 级引用校验**：把答案拆成原子陈述，逐条对证据判支持 | 句级只能抓"整句没出处"，抓不到"抄两句 + 补一句常识"——那个缺口现在只能写在文档里，没有机制填 | 3~5 天（拆句器 + 逐 claim 对齐） | 用模型拆句 = 引入模型裁判，撞铁律；只能规则拆句（标点 + 连接词），拆不准会造出假阳性 |

三条判断：

- **第 1 项必须排第一，因为它决定后面所有数能不能被引用。** 阈值没定之前，消融做出来只是四个没有通过线的数。
- **第 2 项和第 3 项的顺序可以换，但不许省。** 消融回答"该不该加 rerank"，二级校验回答"引用对不对"——前者是优化，后者是 REQ-08 的成立条件。
- **第 5 项现在做等于跳级。** 句级校验自己都还分不开同主题邻块，先做断言级只会把不确定性乘一层。

**不建议投的**：

| 不做 | 为什么 |
|---|---|
| 检索轨迹可视化 | 好看，但没人按它做决定；真正的观测点是四值分布与负控非空数 |
| 多路加权融合调参 | RRF 本来没有权重；改成加权求和要先有基线，而混合检索的基线还没有 |
| 引用可信度评分（0.87 那种） | 只制造新的误读；要么挂上引用，要么不挂 |

#### 4.3 实测基线

来源 `evals/baseline.json`（2026-11-02T09:47:27，库指纹 `5455a01a2e3a`，63 文档 / 439 块）。语料是 C# 版那 63 篇制造业 PDF；**Python 版是同语料、同题集的对照目标，不是现状。**

| 段 | 数 | 判据 | 结论 |
|---|---|---|---|
| 索引 | 63 / 439 / 439 / 439 / 63，五类全 0 | 三处同时写、数量相等 | 通 |
| 切块 | 376 条接缝、34 处异常、32 块、**7.29%** | ≤ 5%（目标线） | 不通过 |
| 检索 | 40 题 → 有效 **32** 题，HitRate **0.812**、MRR **0.588** | 现在**没有通过线** | 半通 |
| 分档 | literal 7 题 0.857 / 0.671；paraphrase 23 题 0.783 / 0.527；ambiguous 2 题 1.000 / 1.000 | 只看改写档算真实体验 | 参考 |

三个必须记住的点：

1. **7.29% 是"不通过"，不是"接近通过"。** 块从半句开始时，模型拿到没有主语的文字，而引用角标照样能对上——这是可用里唯一不触发任何其它告警的错误。
2. **paraphrase 0.783 才是真实体验**，literal 0.857 只证明索引通了（原文标题就是问题，必然命中）。
3. **基线里没有拒答段。** `evals/self/run_refusal_eval.py` 存在，但没进 `evals/__main__.py` 的三段计划，阈值也没定——所以"闸"这件事目前一个数都没有。

#### 4.4 旧版 21 项摘要

| 状态 | 项数 | 是哪几项 |
|---|---|---|
| 通（端到端） | 2 | 可用五、可用七 |
| 通（自动断言） | 5 | 可用一（脚本）、可用八（接口）、可核二（函数）、不编二（管道）、不编七（单测） |
| 通（人工目视） | 3 | 可核四、可核五、不编四 |
| **不通过** | 4 | 可用二（切块）、**可用六（零检索）**、**可核一（零角标）**、可核三（判别力） |
| 半通 | 3 | 可用三（有数无通过线）、不编一（只覆盖算术）、不编三（只覆盖文案来源） |

**牙齿分布：有 11 / 半个 3 / 无断言 3 / 无从判断 2 / 无验证 2。** "有牙齿"不等于"通过"——那 4 条红的恰恰因为抓到了真问题。这个区分以后每次都要看：不通过证明断言有效，通过但没牙齿才是真正该怕的。

#### 4.5 最该防的是"永远不执行的分支"

C# 版的反面教材，逐字记下来：

> `SufficiencyGate` 有 36 条测试全绿，两个阈值是 `null`，`Judge` 第一句就是"没配齐 → 未判定"。函数通、管道通、状态码通，**运行时一次都走不到拒答那个分支**。

这不是测试写得不好，是**测试的层级比失效的位置低一层**：36 条断言证明"给定数值时算术对"，证明不了"线上有数值"。同类的形状还有三种：只有一条候选时走不到间隔比较；候选过滤把远点全剪掉时走不到"距离够远"；前端没接状态码时走不到拒答卡。

四条机制，按性价比排：

| # | 机制 | 具体做法 | 防的是哪种空分支 |
|---|---|---|---|
| 1 | **启动期校验，缺则失败** | 装配时检查每个判定阈值有消费者且非空；缺 → 进程起不来，不是给出"未判定" | "配置没填"被伪装成"系统诚实" |
| 2 | **探针用例** | 一条端到端测试：跑一个已知库外问题，断言①判定=资料不足 ②生成长度=0 ③状态=`refused`。三样一起断言，缺一不算 | 函数通了、管道没接 |
| 3 | **评测报分布** | `python -m evals run` 多打印一行四值分布。**未判定占 100% 与"每条都判了"一样是红灯** | 闸没接线的静默状态 |
| 4 | **改坏法** | 每补一条验证，先故意把功能改坏一次，看它红不红；不红就是白写 | 恒真式断言（`gap < 0.20` 在覆盖率永远返回 0 时照样绿） |

第 1 条与 D-12 的关系要说清：**D-12 说的是函数层——阈值可空，空则结论落"未判定"，不能用 0 假装配置过。本节加的是部署层——不允许带着空阈值上线。** 两层不冲突，缺了第二层，D-12 的"未判定"就成了最好的藏身处。

判据一句话：**"它能报出自己执行过几次"，比"它测过几次"重要。**

### 五、不做与边界

#### 5.1 产品边界

| 不做 | 为什么 | 什么条件下重开 |
|---|---|---|
| 不检索直接答（通用问答） | 一旦允许，权限与引用同时失效——没有证据就没有可核对象 | 归 F7 通用对话；本域不实现，也不在资料不足时自动转通用对话兜底。F3 只做有证据的问答 |
| 改写 / 翻译 / 扩写 | 一做创作，引用就失去意义（创作没有出处） | 不重开，同上 |
| 多轮复杂任务编排（"帮我整理一份报告"） | 那是 Agent 编排，与"查知识"是两种产品；混进来会让本域的判据失去边界 | 出现独立的任务型需求且单独立域时 |
| 主动推送 / 定时摘要 | 第一版是"问—答"模型 | 有明确的订阅/告警类客户合同 |
| 多跳检索 / GraphRAG | 没有基线之前加检索编排，等于同时改两个变量，改完说不清是哪一层变了 | 消融证明 miss 集中在跨块题，且 A-06 的 TopK 5→10 试验做完（那时 beyond_retrieval 若变成正例，说明是参数问题不是编排问题） |
| 查询改写 / 扩展（query rewriting） | 多一次模型调用；更要紧的是"问题就是用户原话"这个前提消失，题库标准答案要跟着重写，历史基线全部作废 | paraphrase 档明显低于 literal 且 miss 集中在词面不匹配——现在 0.783 对 0.857，看不出这个信号 |
| 同义词表 / 词典分词 | 又一份带版本的隐藏状态，换一版数字就漂 | 两字切分在某类查询上系统性失败，且 LIKE 兜底也救不回来 |

#### 5.2 技术做法

| 不做 | 为什么 | 什么条件下重开 |
|---|---|---|
| 用模型判"答案够不够"或"引用是否忠实" | 不可复现、不可复算，撞"不得由模型当门禁"这条铁律 | 不重开 |
| 给模型否决权（申诉权） | 否决层只读判定；给了申诉权的闸等于没有闸，而且事后说不清是谁放行的 | 不重开。误拒率高时放宽阈值，不是给它申诉 |
| 多层"未判定" | 未判定只有"缺向量 / 阈值缺失"两种成因，多一层就多一个说不清的状态 | 出现第三种可命名的成因时 |
| 引用可信度评分 | 一个 0.87 只制造新的误读；用户要的是"挂上或没挂上"，不是"大概可信" | 不重开 |
| 原文页面跳转 + 高亮 | 页码精度只到"第 1 页"，撑不起跳转。回原文退到片段卡片 | 解析器能稳定给出页内坐标（bbox）且跨版本不漂 |
| 多路加权融合调参 | 现在用 RRF，没有可调的权重；改成加权求和要先有基线 | 混合检索基线出来，且 RRF 明显差于加权 |
| LangGraph 当骨架 | 只接管调度不管执行，记录权旁落；F4 的轨迹会对不上 | 一次 run 的编排复杂度超过 `agent/loop.py` 的三个守卫能表达的范围 |
| LlamaIndex 接管存储 | docstore 会吃掉块边界，40 题 gold 挂在块边界上，接管即题库与基线一起失效，且不报错 | 不重开。允许用它的切块器与 embedding 客户端，表和检索 SQL 自己写 |
| 引用记录不落库（现状） | — | 这是缺口不是边界，见 REQ-21 / 可核六，必须补 |

#### 5.3 有条件暂缓（不是不做）

| 暂缓 | 等什么 | 为什么现在不做 |
|---|---|---|
| 交叉编码器重排 | 混合检索基线 + 消融（§三 第 2 项） | 会同时改排序和分数分布，做完就失去"改分词前后差多少"的对照 |
| 换解析器（MinerU / docling） | 先有解析失败的显式上报路径 | 改切块边界 → 块编号全变 → 题库标准答案全部作废，而这件事不报错 |
| claim 级引用校验 | 二级校验有判别力之后 | 句级都分不开同主题邻块，断言级只会把不确定性乘一层 |

两类不能混：暂缓的等着就能做；5.1 和 5.2 两张表是无条件的，等多久都不做。

#### 5.4 一条通则

**任何新配置项必须有消费者。** 没有消费者的配置比没有这个配置更糟——下一个人（或一个 agent）会以为对应的机制还在，然后在一个永远不会来的人身上等结果。

配套的两条：配置为空时**启动失败**，不要静默降级（§4.5）；配置写了 0 就是 0，系统不替人猜"这是没配吧"（D-12）。
