# 未解决问题台账

**这份文件只有一条规则：每个 D 结束，把没解决的问题写进来。**

不写会怎样：问题只活在那一天的对话和 `reports/` 里的报告里，而 `reports/` 是 gitignore 的。
过两周回来看，"D8 那三条残余风险是什么"要靠翻聊天记录——等于没有。

## 维护约定

1. **每个 D 结束时必做**：新增的问题追加到对应表格，给编号 `U-nn`。
   哪怕当天全部通过，也要在「变更记录」写一行"Dn：无新增"。
2. **只有两种情况能离开「待处置」**：
   - **验证修复** → 移到「已关闭」，必须附**可复跑的验证方式**（测试名或命令），不附不算；
   - **明确接受** → 移到「已接受的风险」，必须写清**为什么可以接受**，谁决定的。
   不能因为"这个 D 做完了"就自动消失。
3. **一条问题只在一处**：`docs/验收/现状.md` 是台账口径（哪条验证项过了/没过），
   本文件是**问题口径**（有什么坑、谁来填）。两边用编号互相指，不重复抄内容。
4. **不进本文件**：已经没人会做、也没人需要知道的东西。这是待办，不是日记。

## 三、已接受的风险（不是待办，别再提）

| 问题 | 为什么可以接受 |
|---|---|
| 备份解密依赖同一把 `AWB_SECRET_KEY` | 设计如此（`db/crypto.py` 写明）。换密钥 = 全部密文作废，需重存凭据；**轮换流程**属于第二次备份演练，不在本次验收范围 |
| 第三方 SDK 自身的 DEBUG 日志 | 判据断言的是 `agentworkbench.*` 的记录。生产默认级别 WARNING；`openai` 库打不打请求头是它的事 |
| 未配置 embedding 时退回 `HashEmbedder` | 是合法部署态（离线、评测库），装配层落 WARNING 且设置页显示实际模式。**不是**静默降级 |
| 覆盖率只记数不判（`coverage_threshold=None`） | 词面覆盖率在真实语料上不可用（正确答案最低 0.368），设阈值只会误伤。这是 D8 测过之后的决定——但它不等于 U-03 可以一直不解决 |
| `U-16` 平台管理员可把「上游地址」指向内网任意地址（SSRF 残余） | 这个端点**本来**就是「打一个用户给的地址」，而本地部署的主场景是 `127.0.0.1:11434`（Ollama）——拦内网等于把功能废掉一半。该账号本来就能改这台机器的全部配置，应用层挡不住它。D9 已拦掉「永远不合法」的三类（非 http(s)、云元数据、URL 带凭据）。真正的边界在网络出口策略，不在应用层 |
| `U-20` 匿名者可用 5 次错口令锁住任意已知邮箱 15 分钟 | 这是「账号锁定」这个机制的固有代价：不锁就挡不住爆破，锁就能被用来封门。红队确认响应与「口令错」逐字相同（无法从响应区分），到期自愈也已实测。没有做成按 IP 计数：单机部署没有可信的 `X-Forwarded-For`，按 IP 计数会被一个头绕过 |
| `U-21` 同内容去重时回显先上传者的文件名/时间/错误 | 同团队的文件名本来就在文档列表里全可见，**不构成越权**。真正的毛病是「我传的名字被静默丢弃」这句体验话，改 UI 即可，不是安全问题 |
| `U-18` 邀请的第一问仍会泄漏「这个邮箱注册过」 | 全局唯一邮箱 + 允许凭邀请自建号，这两条合起来必然能从「400 vs 201」读出存在性。D9 已经把**无限次探测**改成一张邀请一次（烧令牌）。要彻底消掉得让邮箱按团队唯一，那会改变登录方式，属于产品级决定 |
